# 活人化表达层 HUMANIZATION V1 TEST

> 状态：实验规则。它不替代“事实可靠、内容价值分级、双脊柱、Hook后置、高热度审核、观众价值审核”，而是位于这些结构已经成立之后的最终重写层。
>
> 目的：解决“逻辑正确、信息完整、结构优秀，但听起来仍像 AI 写的”问题。
>
> 参考来源：用户提供的《文案调整方案_转换副本.docx》以及宇树 V5/V6/V7 对照试写。参考文档强调：先学习已有优秀短视频文案的表达机制，再创作；前 1—3 句要能吸引观众；段落之间要有衔接和持续观看动力；多讲案例、少讲理论；语言犀利、少啰嗦；并根据真实发布数据继续调整。本文只吸收这些写作机制，不复制原句，不把“通过某种原创检测”作为写作目标。

## 1. Humanization 不是“加口语词”

禁止把活人化理解为：

- 到处加“其实、就是说、你知道吧”；
- 强行加网络梗；
- 故意写错句子；
- 把所有句子变短；
- 用大量感叹号；
- 用“兄弟们、家人们”制造伪口语。

真正的活人化，是让观众能听到一个人在“发现、判断、犹豫、解释和落地”的过程，而不是只听到一个系统在交付答案。

## 2. 结构先成立，再把结构藏起来

内容智能阶段可以使用：

- S/A/B/C/D 信息分级；
- 核心发现；
- 观点树；
- 信息脊柱；
- 好奇脊柱；
- 判断工具。

但最终口播稿不应机械暴露这些内部结构。

例如内部可以是：

```text
任务门 → 重复门 → 系统门
```

最终表达可以自然变成：

```text
它到底替谁干什么？
↓
这件事它能不能天天都做好？
↓
真出了问题，谁接着管？
```

原则：**框架服务作者，不要求观众看见框架。**

## 3. 允许“真人缓冲句”

原双脊柱规则继续保留“每 5—10 秒应有有效推进”的目标，但修正为：

> 每 5—10 秒必须发生一次有效推进；推进之间允许存在 1—2 句短缓冲，只要它们承担情绪、转折、理解或说话节奏功能。

允许的缓冲句示例：

- “这个事挺有意思。”
- “说白了，已经开始干正事了。”
- “后来我想明白了。”
- “你看，这两句话放一块儿就有意思了。”

这些句子不一定增加新事实，但能让听众跟上“一个人的思考过程”。

禁止无功能水句。如果删除后完全不影响情绪、节奏、理解和人物声音，则仍应删除。

## 4. 理论后置，先让观众经历问题

优先顺序：

```text
具体事件 / 具体矛盾
→ 观众自然产生问题
→ 生活化解释 / 案例
→ 再抽象出判断
```

避免：

```text
先宣布一个三点框架
→ 再逐条证明
```

除非教程型内容本身就需要明确步骤。

知识型内容优先让“方法从故事里长出来”。

## 5. 抽象概念必须经过生活翻译

出现以下词时必须警惕：

- 商业化成熟度；
- 稳定重复能力；
- 系统性承接；
- 使用成本；
- 可靠性；
- 价值闭环；
- 底层逻辑。

不是禁止使用，而是至少问一次：

> 普通人生活里有没有一个更容易立刻理解的例子？

例如：

“长期稳定重复”
↓
“扫地机器人十次有两次卡在沙发底下，你都会骂它；消防机器人能不能接受这种概率？”

生活类比必须真实、简单、服务理解，不能为了幽默强行插入。

## 6. 人的思考痕迹

最终稿至少检查是否存在以下一种自然痕迹：

- “我原来以为……后来发现……”；
- “我继续往下看，看到一句……”；
- “这两件事放在一起，我才觉得有意思”；
- “这个地方我一开始也没想明白”；
- 从具体事实自然形成判断，而不是开篇就拥有标准答案。

禁止伪造个人经历。只有真实阅读、真实测试、真实观察或明确的分析过程才允许用第一人称。

## 7. 降低“工整感”

以下模式连续出现时，通常会增加 AI 感：

- 第一、第二、第三；
- 不是 A，而是 B；
- 这意味着……这说明……这表明……；
- 所以我们可以得出；
- 这套方法不仅适用于 X，也适用于 Y；
- 每段长度高度一致；
- 每段都以总结句结束；
- 每一句都像可截图金句。

这些结构不是禁用，但必须避免连续重复。

允许句长变化、停顿、短句、插入解释，让节奏更接近真实说话。

## 8. 金句必须像人会说的话

金句优先级：

1. 好说；
2. 好懂；
3. 好记；
4. 最后才是“高级”。

如果一句话读出来明显像作者在“制造金句”，应优先降级表达。

例如：

较抽象：
“演示看的是上限，真正使用看的是下限。”

更生活化的延伸：
“能做出来，叫技术；别人敢天天用，才叫产品；用了以后还愿意继续掏钱，才有机会变成生意。”

两种都可以保留，但一条稿件不应塞太多金句。

## 9. 结尾先收人，再收框架

禁止结尾像论文摘要：

- “综上所述”；
- 再次完整复述三点；
- 强行把所有内容扩大到人生、时代、社会。

优先让结尾回到一个具体画面、具体判断或自然问题。

例如：

“什么时候有一件事，我们已经习惯交给它去干了，甚至干完以后都懒得再看它一眼。到那个时候，机器人离我们的生活才是真的近了。”

## 10. 活人化审核清单

最终稿完成后，逐项回答：

1. 如果去掉标题和编号，这段话像不像一个真实的人连续说出来？
2. 是否能听到“思考过程”，而不只是标准答案？
3. 是否有至少一个具体事件、场景或生活类比承载抽象观点？
4. 内部框架是否被自然表达，而不是完整展示给观众？
5. 是否允许少量有功能的缓冲句？
6. 是否存在连续三段同一种句式？
7. 是否存在“为了金句而金句”？
8. 是否存在不必要的专业词或抽象词？
9. 读出声时，是否有自然停顿和长短句变化？
10. 是否出现现实中作者大概率不会说的书面表达？

任意 3 项明显不通过，必须执行 Humanization 重写，不得直接交付。

## 11. 与双脊柱的关系

Humanization 不允许破坏双脊柱。

正确关系：

```text
内容智能决定：讲什么、为什么继续
Humanization 决定：像谁在说、怎么自然说
```

如果为了“像人”导致：

- 事实边界模糊；
- 核心观点丢失；
- 大量水句；
- 好奇链断裂；
- 时长失控；

则 Humanization 失败，需要回退重写。

## 12. 当前实验结论

宇树 V5/V6 → V7 的人工对照显示：

- 框架隐藏后，自然度明显提升；
- 理论后置、先讲消防案例，理解更顺；
- 增加“扫地机器人”生活类比后，抽象的稳定性问题更容易理解；
- 少量缓冲句让稿子不再像每句都在完成任务；
- 金句从抽象概念转向更可说的表达后，更像真人口播。

以上只是人工质量判断，尚未经过真实录音与发布数据验证，因此状态仍为 `EXPERIMENTAL`。
