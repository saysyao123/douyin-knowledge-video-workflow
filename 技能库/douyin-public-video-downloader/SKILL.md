# 抖音公开视频下载

## 目标与边界

本技能服务于抖音公开视频的研究、对标和内部素材分析。默认项目根目录是 `D:\整体视频流程重建`，下载视频、清单、校验结果和失败记录都放在该根目录下；面向用户操作的目录使用中文名，例如 `素材库`、`下载记录`、`第一轮分析资料`。

只处理：

- 用户明确提供或授权采集的公开抖音账号、作品页或视频页；
- 公开播放器能够正常展示、且浏览器页面暴露可下载媒体地址的内容；
- 研究用途的本地保存，不默认用于再发布、搬运或商业分发。

禁止：

- 读取用户 Chrome/Edge 的 Cookie、导入登录态、操作私密账号或绕过登录；
- 绕过验证码、风控、付费墙、地区限制或第三方访问控制；
- 使用不明第三方“解析/去水印”站点；
- 将临时签名媒体 URL 当作长期来源；长期记录必须保存公开视频页 URL、作品 ID、采集时间和文件 SHA-256；
- 在无法确认来源或完整性时，把部分下载、预览或截图称为已下载视频。

## 默认交付结构

如果用户没有另行指定，使用以下结构：

```text
D:\整体视频流程重建\
├─ 素材库\对标账号视频\<中文账号名>\
├─ 下载记录\抖音公开视频\<采集批次>\
│  ├─ 下载清单.json
│  ├─ 下载结果.json
│  └─ 失败记录.md（如有失败）
└─ 第一轮分析资料\对标视频索引.md
```

技能本体的技术目录名遵循 Codex 的英文命名约束；项目内的素材、导入和记录目录仍必须使用中文名。技能本体的项目源文件位于：

`D:\整体视频流程重建\技能库\douyin-public-video-downloader\`

## 标准执行路径

### 1. 先固定采集规则

在下载前明确并记录：账号名、账号主页或视频页、数量、选择规则（最新/最火/指定作品）、采集日期、用途和是否允许替补。

若用户只说“下载 N 个”：默认选择公开可见的近期作品，不把置顶、合集封面或搜索结果页本身当作视频；不能声称“最火”，除非有可核验的公开点赞/评论/收藏证据。

若要求固定数量：某个候选不可访问时，只允许使用同一账号、同一选择规则下的明确替补，并在 `下载清单.json` 中记录 `substituted_for` 与原因；不得静默替换。若用户没有授权替补，应交付部分结果并列出失败原因。

### 2. 建立候选清单

先建立 JSON 清单，再下载。每项至少包含：

```json
{
  "account": "账号显示名",
  "account_folder": "中文账号目录名",
  "aweme_id": "作品ID",
  "title": "公开页面标题",
  "published_at": "页面可见发布时间或 null",
  "selection_rule": "latest|hottest|specified",
  "source_url": "https://www.douyin.com/video/作品ID",
  "media_url": "本次页面临时暴露的媒体地址",
  "filename": "01_作品ID.mp4",
  "collected_at": "Asia/Shanghai ISO 8601 时间",
  "substituted_for": null,
  "notes": "页面证据或限制"
}
```

`media_url` 只供当前下载使用，签名会过期；最终分析索引以 `source_url` 和 `aweme_id` 为准。标题、时间和热度属于页面元数据，必须标注采集时间，不能用推断补齐。

### 3. 用公开页面获取当前媒体地址

使用 Codex 的应用内浏览器打开每个 `source_url`，保持公开、只读、无登录。页面加载后，等待播放器真正出现，再在短时间窗口内轮询 `video`/`source` 元素。优先选择匹配 `douyinvod.com` 或 `aweme/v1/play` 的当前地址；示例检查逻辑：

```javascript
const v = document.querySelector('video');
const urls = Array.from(document.querySelectorAll('source'))
  .map(s => s.src || s.getAttribute('src'))
  .filter(Boolean);
return {
  urls: [...(v?.currentSrc ? [v.currentSrc] : []), ...urls]
    .filter(u => /douyinvod\.com|aweme\/v1\/play/i.test(u)),
  duration: v?.duration || 0
};
```

优先使用 `source.src` 中的直接媒体地址；`blob:` 是播放器内部地址，不能直接交给下载器。签名地址通常短时有效，提取后应立即下载，不要批量提取一遍再长时间等待。

如果页面只显示登录、验证码、权限错误，或在一次延长等待后仍未暴露媒体地址：记录失败状态并停止该条。不得读取本机浏览器 Cookie 或改用绕过方案。

### 4. 原子下载

将浏览器得到的临时媒体地址交给本技能目录中的 `scripts/download-public-assets.ps1`，或等价地执行同样的规则：

- 请求使用普通浏览器 User-Agent 和 `https://www.douyin.com/` Referer；
- 先写入目标文件旁的 `.part` 临时文件；
- 目标已存在时，先校验现有文件，合格则跳过，不覆盖；
- 下载失败、文件过小或容器不可识别时，保留失败记录，不把 `.part` 改名为成品；
- 只有通过基础媒体识别后，才原子移动为 `.mp4`。

当前实测的公开页面路线是“应用内浏览器提取直链 + curl 下载”。`yt-dlp` 可以作为诊断工具，但不是本技能的唯一依赖；若它提示需要 fresh cookies，立即回到公开页面路线，不导入 Cookie。

### 5. 逐文件完整性校验

下载批次必须运行 `scripts/verify-video-assets.ps1`。合格条件全部满足才算成功：

- 文件存在、扩展名为 `.mp4`、无 `.part`/`.tmp`/`.crdownload` 残留；
- 文件大小大于最小阈值；
- FFprobe 能读取容器、时长、分辨率；
- 至少有一个视频流和一个音频流；
- 视频编码和音频编码记录在结果中，常见 H.264/AAC 不作为唯一硬编码条件；
- FFmpeg 使用 `-v error -xerror` 从头到尾解码，退出码为 0；
- 生成完整 SHA-256，并将大小、时长、分辨率、编码、校验状态写入结果 JSON/分析索引。

单纯能点击播放、页面出现缩略图、文件有 `.mp4` 扩展名或下载器返回 200，都不等于通过。

### 6. 形成可复盘记录

最终记录至少包含：批次时间、选择规则、账号、作品 ID、标题、公开页面 URL、页面可见发布时间、文件相对路径、字节数、时长、分辨率、编码、SHA-256、校验结果和备注。

对失败项记录状态，例如：`page-access-blocked`、`media-url-not-exposed`、`auth-required`、`captcha-required`、`download-failed`、`validation-failed`。交付时明确成功数/计划数；未达到数量时不声称完成整批。

## 稳定性与重跑规则

- 同一作品使用 `aweme_id` 作为去重键；重新运行先查清单和文件校验结果。
- 每次运行创建新的中文批次目录或追加新批次记录，不覆盖历史索引。
- 签名媒体地址不复用；重跑时重新打开公开视频页并重新提取。
- 账号主页只能用于发现候选，最终来源必须落到具体作品页。
- 选择“最火”时保留热度字段和证据来源；没有证据就降级为“近期公开样本”。
- 下载视频只作为研究素材，不自动生成口播稿、不自动发布、不代替事实核验。
